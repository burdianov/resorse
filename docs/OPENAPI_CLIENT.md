# OPENAPI TYPED CLIENT — task F018

The API client foundation: typed DTOs generated from FastAPI's OpenAPI schema, one shared Axios instance with
normalised errors, and the TanStack Query provider. Sources: `BIG-PROMPT.txt` §6.2e, §8.3b, §9.2–§9.4;
`docs/ARCHITECTURE.md` §3, §5, §10. Drift is enforced in CI by **F061**; this task builds the pipeline the check
watches.

## 1. The pipeline — schema in, types out, both committed

```text
backend/app/…  (FastAPI routers + Pydantic DTOs)
      │  uv run python -m scripts.export_openapi        ← backend/
      ▼
backend/openapi.json                                   ← committed
      │  pnpm run api:types                              ← frontend/ (openapi-ts.config.ts)
      ▼
frontend/src/lib/generated/api/{index.ts,types.gen.ts} ← committed, never hand-edited
```

- **The schema is generated by importing the app** — no server, no database, no network — so the same command
  works in CI. Output is `sort_keys=True` + fixed indent + explicit LF, which makes regeneration
  **byte-stable**: re-running both steps changes nothing (`git diff` clean), verified by hashing the artefacts
  across repeated runs.
- **Both artefacts are committed.** They are the reference the F061 drift check compares against: regenerate both,
  then `git diff --exit-code -- backend/openapi.json frontend/src/lib/generated`.
- **Regenerate after any API change.** A route added, renamed or whose response model changed makes the committed
  types stale; the next `api:types` run refreshes them, and the diff in the commit is the review surface.

```powershell
cd D:\resors\backend;  uv run python -m scripts.export_openapi   # → backend/openapi.json
cd D:\resors\frontend; pnpm run api:types                        # → src/lib/generated/api/
```

### Why `@hey-api/openapi-ts` (0.99.0), and why types only

The generator runs the **`@hey-api/typescript` plugin alone**: this project wants DTOs, not a generated SDK. A
generated SDK would be a second transport competing with `src/lib/api.ts`, which owns error normalization and the
401 policy — one client, one error shape, no drift between two request paths.

Two alternatives were checked against the npm registry (2026-10-09) rather than assumed:

| Tool | Version | Verdict |
|---|---|---|
| `openapi-typescript` | 7.13.0 (2026-02-11) | Rejected: declares peer `typescript ^5.x`. With TypeScript 6.0.3 installed, pnpm's `auto-install-peers` resolves a **second TypeScript copy** for it. Last published before TS 6 existed. |
| `orval` | 8.41.0 | Rejected as too broad: it generates per-endpoint Query hooks and a client, duplicating the hand-written client and the centralised query keys. |
| **`@hey-api/openapi-ts`** | **0.99.0 (2026-06-22)** | **Chosen**: peers `typescript >=5.5.3 \|\| >=6.0.0` — TS 6 is explicitly supported; engines `node >=22.18.0` (Node 24.14.0 ✓); runs as a pinned devDependency CLI, no runtime code. |

The generated file is **committed but not hand-edited**; corrections to generated UI components follow
ARCHITECTURE §5, while this file's contract is the opposite — never edit it, regenerate it.

## 2. The client — `src/lib/api.ts`

One Axios instance; every feature request goes through it. Three decisions are compiled in:

- **Same-origin, relative paths.** `baseURL` is empty, so the schema's own `/api/v1/health` resolves against
  whichever host served the SPA (Vite proxy in development, Caddy in production — ARCHITECTURE §2). Cookies are
  first-party and there is no CORS preflight. `VITE_API_URL` is the escape hatch §9.3 allows: an **origin**
  (`https://api.example.com`) or unset — never a secret.
- **Every rejection is an `ApiError`** (`src/lib/errors.ts`). Feature code never inspects an Axios error.
- **A 401 is re-resolved once, never refreshed.** There is no refresh endpoint under the opaque-cookie session
  design (ARCHITECTURE §3) and no token in JavaScript. A 401 instead means the client's auth state may be stale:
  an `UnauthorizedHandler` re-resolves it, and if the session is still valid the original request is retried
  **exactly once**. Concurrent 401s share one resolution (single-flight), and `/auth/*` requests are never retried
  — a 401 from login is the answer, not staleness (§6.2e).

`setUnauthorizedHandler()` is the seam: **F032** registers it once the session exists; until then a 401 surfaces
as an `ApiError` and nothing pretends to recover.

```ts
import { api } from '@/lib/api'
import type { HealthApiV1HealthGetResponse } from '@/lib/generated/api'

const health = await api.get<HealthApiV1HealthGetResponse>('/api/v1/health')
```

Each endpoint's path is written once, beside its generated response type. A renamed route changes the generated
type's name, so call sites fail to compile rather than 404 at runtime.

## 3. The error contract — `src/lib/errors.ts`

FastAPI's shape is `{ "detail": <string | validation-array> }` (ARCHITECTURE §10). The client normalises it once:

| Case | `kind` | `detail` (safe to display) | Extras |
|---|---|---|---|
| 4xx with a `detail` string | `http` | the backend's message | |
| 4xx without a usable one | `http` | status-based fallback copy | |
| 422 | `http` | "Some of the submitted values need attention." | `fieldErrors` — dotted paths (`items.0.name`) parsed from Pydantic's `loc`, minus the `body`/`query` prefix |
| 5xx | `http` | **our copy, never the body** | `status` |
| No response (DNS, refused, timeout) | `network` | "The server could not be reached…" | `status === null` |
| Aborted (`AbortSignal`) | `canceled` | — | |
| A plain thrown `Error` | `unknown` | its message | |

Two safety rules are enforced here rather than left to call sites:

- **A 5xx body is never displayed.** It may be a stack trace, a proxy's HTML page or internal detail; §6.2f's
  "no data leak" applies to error UI. 4xx messages are shown, because our own backend writes them for the user.
- **Cancellations are marked, not treated as failures.** TanStack Query aborts in-flight queries on unmount;
  surfacing that would toast at a user who just navigated.

`requestId` carries the `x-request-id` header when one exists (F060 adds it server-side) so error reports can
reference the server's correlation id.

## 4. The query layer — `src/components/providers/query-provider.tsx`

Provider stack lives in `src/app/providers.tsx` (theme → query → toaster), matching ARCHITECTURE §5.

| Decision | Value | Why |
|---|---|---|
| `staleTime` | 30 s | §9.2's source-like freshness window |
| Query retry | never on 4xx or cancellation; once otherwise | a 4xx is a verdict; network/5xx are transient |
| Mutation retry | never | a write may not be idempotent |

**Where a failure becomes visible** — the rule is "the toast speaks only when nothing else can":

| Failure | Surface |
|---|---|
| Cold query failure (nothing rendered) | the page's `ErrorState` with Retry (F017) — no toast, it would say the same thing twice |
| Background refetch failure (data already on screen) | toast — otherwise the staleness is invisible |
| Failed mutation | toast — nothing else can show it until F019 maps field errors onto forms |
| Cancellation | nothing |

Query keys are centralised in `src/lib/query-keys.ts`. **Identity rule:** data that belongs to the signed-in user
must carry that user's id in its key (`['users', userId, …]`, F041), so a cache entry can never be served across
an account switch even if F032's cache clear is ever missed.

## 5. Tests — MSW, no network, no mocks of our own code

`src/testing/msw-server.ts` exports the MSW server; `src/testing/setup.ts` starts it (`onUnhandledFrame: 'error'` —
an unmocked request fails loudly), resets handlers between tests and closes it at the end. Test files declare only
the endpoints they exercise.

| File | Covers |
|---|---|
| `tests/lib/api-client.test.ts` | typed GET/POST/204, 4xx/422/5xx/network/cancel normalization, the 401 policy (retry once, single-flight, auth-path exclusion, no second retry) |
| `tests/lib/query-provider.test.tsx` | client defaults, retry policy, cold vs background failure surfaces, mutation toast, injected client |

The toast assertions run against the real `<Toaster />`; nothing in the error path is mocked.

> **Trap recorded:** MSW 3 renamed `onUnhandledRequest` to **`onUnhandledFrame`**. The old key is silently ignored
> by the types and at runtime, which downgrades a strict test setup to a warning without failing anything.

## 6. Adding an endpoint — the recipe

1. Implement the route + response schema in the backend.
2. `cd backend; uv run python -m scripts.export_openapi`
3. `cd frontend; pnpm run api:types` — the new DTOs appear in `src/lib/generated/api`.
4. Call it from the owning feature module (`features/<feature>/api.ts`): `api.get<TheGeneratedResponseType>(path)`.
5. Wrap it in `useQuery`/`useMutation` with a key from `src/lib/query-keys.ts`, and test it against MSW.
